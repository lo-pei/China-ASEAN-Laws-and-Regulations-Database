# 00 · 目录结构与维护指南

> 本文件说明 CALR 项目**每个目录的用途与边界、命名规范、归档规则、关键文件清单**。
> 目标：任何人拿到仓库，能在一页内知道"东西该放哪、什么不能动、改完怎么验证"。
> 最后整理：2026-10-29（工程文档与比赛材料分离）。

---

## 一、整理原则

1. **仓库只收可交付内容**：源码、数据、文档、规范、交付物、比赛材料。模型、数据库、缓存、历史脚本留在本地 `_work/`。
2. **单一权威源**：数据以 `prototype/data/laws/` 为唯一权威；**工程文档以 `docs/` 为准**；**规范以 `rules/` 为准**；**比赛材料以 `materials/` 为准**。
3. **按受众分层**：`docs/` = 工程文档（怎么写、怎么跑、怎么运维）；`rules/` = 给 agent 的机器可校验契约；`materials/` = 给评委/申报系统的报告、路演与提交物。
4. **历史只标记、不删除**：过期文件移入 `_archive-YYYY-MM-DD/` 并写清替代关系，避免误引。
5. **路径改动同步改引用**：移动/改名必须在同一次改动中更新 `README.md`、`docs/`、`materials/`、`rules/` 中的引用。
6. **新增顶层目录视为有意行为**：`.gitignore` 用显式排除，新目录会出现在 `git status` 中（不会被静默忽略）。

## 三、各目录细则

### 3.1 `prototype/` — 前端与权威数据

```
index.html            入口；file:// 直接打开走静态模式，http(s) 走 API 模式
assets/js/            app.js + core/（store/search/qa/api/fulltext/i18n/router/citation…）
                      + views/（home/search/law/assistant…）+ ui/
assets/css/           tokens / base / components / views / home-v2 / mobile
assets/img/           站点图片、12 国系统配图（首页照片放置说明见 assets/img/README.txt）
data/laws/            ★ 权威存储：<法规ID>.json + index.json + 清单 CSV
data/{cn,intl,fulltext}/   条文分卷（派生，按需加载）
data/trans/          译文层分卷 + manifest + PROVENANCE（只增不改）
data/title-zh/       中文标题档案 + artifacts/ 批次留痕（只增不改）
data/*.js            前端数据入口：dataset-core/extra、cn/intl-catalog、i18n-*、bm25-idf…
```

- **边界**：`prototype/` 必须自足（A1–A11 检查），不得引用 `_work/` 或仓库外路径。
- **禁止**：手改派生分卷与 catalog；把译文写回原文正文。细则见 `prototype/data/README.md`。

### 3.2 `backend/` — 后端服务

- `build_db.py` 从权威 JSON 建 `data/calr.db`（约 1.2 GB）；`app/` 提供 API；`test_api.py` 13 项自测。
- `data/`（`calr.db`、`vectors/`）**不入库**，由脚本生成。
- 边界：后端不直接改数据；数据更新走 `prototype/data/laws/` 再重建。
- 部署说明：[backend/DEPLOY.md](../backend/DEPLOY.md) 与 [docs/deploy/](deploy/README.md)。

### 3.3 `tools/` — 工具正本

- 根目录：校验器与抓取脚本（`verify*.js` 等）；`templates/`：译文任务/回执模板；`reports/`：评测与补抓快照。
- 边界：**可复现的脚本**；生成型报告放 `reports/`，不要与脚本混放。
- `_work` 中的同名脚本是工作副本，**正本在 `tools/`**。索引见 `tools/README.md`。

### 3.4 `rules/` — 数据契约与红线

- 保留 **7 份权威 SKILL**：条文入库与译文分离、多国法律文本译本生产、法规标题中译、法规标题英译、
  法规标题多语种、越南语法规英译、印尼语法规英译。
- `_archive-2026-10-25/`：旧 `SKILL.md` 快照、`03`/`06` 旧文档、原始需求书、一次性提示词、旧 README。
- 边界：**机器可校验的"怎么做"**；给人读的治理叙事放 `docs/02`。索引见 `rules/README.md`。
- 标题类规范的关系：`SKILL-法规标题中译/英译/越南语/印尼语…` 是**分批翻译任务的回执契约**；
  `SKILL-法规标题多语种规范`（2026-10-29 由 `docs/07-标题多语种规范.md` 迁入）是**跨语种字段模型 + 前端显示 + 验收口径**的上位规范，两者互补、不合并。

### 3.5 `docs/` — 工程文档

- 根目录：`00`（本文件）、`01`–`04` 交付文档、`README.md`（文档索引）。
- `deploy/`：`07` 通用云服务器、`08` B+ 完整版、`09` Windows、`10` Windows 阿里云实测复盘。
- `_archive-2026-10-24/`：34 份历史文档（**不入库**），只供追溯。
- 边界：**只放工程文档**；比赛材料（演示脚本、申报书、报告 docx）在 `materials/`。统计数字以 `docs/README.md §三` 的口径表为准。

### 3.6 `materials/` — 比赛材料

```
README.md             材料总索引（md ↔ docx 对应、重新生成方法、命名与归档约定）
submission/           ★ 官方提交物：仅两份 PDF（产品解决方案Demo.pdf、产品使用说明书.pdf）
reports/              报告与申报：01–04、06 的 docx + 06 申报书 md 源 + 附件2 填写稿 docx
roadshow/             路演与演示：05 演示脚本 md/docx、index.html 交互页、产品 Demo/说明书源文件与渲染件、assets/、tools/
_archive-2026-10-24/  历史 docx/pdf（**不入库**）
```

- 边界：**给人/给评委看的材料**；不放代码与数据。真实产品入口仍是 `prototype/index.html`。
- `reports/01`–`04` 的 md 源是 `docs/01`–`04`（工程文档），本目录只放对外交付的 docx 渲染版。
- 索引、重出方法见 `materials/README.md`。

### 3.7 `_work/`、`.workbuddy/` — 本地目录

- `_work/`：pipeline / data / batches / models。2026-10-25 从 12.85 GB 清理到 3.24 GB；
  2026-10-29 在确认数据自足后删除已入库原始包与旧备份，**29.52 GB → 2.30 GB**，清单见
  `_work/CLEANUP-2026-10-29.md`。
- `.workbuddy/`：外部工具记忆，保持原样，不参与项目构建。

## 四、命名规范

| 类型 | 规范 | 示例 |
| :--- | :--- | :--- |
| 文档 | `NN-中文名.md`（两位编号；md 与 docx 同号） | `01-项目总览.md` / `01-项目总览.docx` |
| 运维文档 | 放 `docs/deploy/`，沿用全局编号，不重编 | `deploy/07-部署指南.md` |
| 比赛材料 | 放 `materials/<类别>/`，沿用全局编号；官方附件保留原名 | `materials/reports/06-项目申报书正文.docx`、`materials/reports/附件2-项目申报书（填写稿）.docx` |
| 代码/脚本 | ASCII kebab-case | `verify-data-home.js`、`crawl-lawphil-batch.py` |
| 数据文件 | 法规用 ID，其余 kebab-case | `CN-REG-0001.json` |
| 目录 | 小写 ASCII；本地工作区用 `_` 前缀 | `prototype/`、`materials/`、`_work/` |
| 归档 | `_archive-YYYY-MM-DD/` | `rules/_archive-2026-10-25/`、`materials/_archive-2026-10-24/` |
| 索引 | 每个目录的入口统一 `README.md` | `tools/README.md`、`materials/README.md` |

**全局编号**：`docs/` 00–04 · `materials/` 05–06 · `docs/deploy/` 07–10；编号全仓库唯一。
**禁止**：文件名含空格、大小写混用、`副本/copy/final/final2/v2/新` 等无信息后缀。
（历史遗留的 `deliverables/07-附件2-…docx` 已于 2026-10-29 去掉 `07-` 前缀，避免与 `docs/deploy/07` 撞号。）

## 五、归档与生命周期

1. **文档被替代** → 移入同目录 `_archive-YYYY-MM-DD/`，并在新文档写明替代关系。
2. **一次性脚本/实验** → `_work/` 内按日期归档，不留在仓库。
3. **交付物重出** → 先改 `docs/` 或 `materials/reports/` 的 md，再渲染 docx；md 与 docx 同号。
4. **数据变更** → 改 `prototype/data/laws/` → 重建派生分卷与 `calr.db` → 跑校验 → 更新文档口径。
5. **删除**：只在确信可重建或已有 tracked 副本时删除；否则归档。
