### 1.3 检索链路实况

**后端 `GET /api/search?mode=hybrid`**（`backend/app/hybrid.py`）
- 两路都用**法规级**：BM25（`search.py`，k1=1.2/b=0.75，标题命中率 +45、标题精确 +45(+CN +25)、无标题 ×0.55、有正文 +12~20、BM25 低于最高分 15% 丢弃）+ 法规向量 top300；
- RRF `k=60`，两路等权 1:1；查询 ≤4 字时向量 ×0.7；
- 国别：问句命中单国 → **召回后硬过滤**（`hybrid.py` 尚未改前置，本轮先改 `/api/qa`）；
- **无 rerank、无相似度阈值**。

**后端 `POST /api/qa`**（`backend/app/qa.py`，2026-10-29 重构）
- 条文级 **BM25 候选**：`search.search` 取 top20 法规 → `article_hits` 取每法前 3 条；
- 条文级 **向量候选**：`vectors.search_articles`，`topk=10×`；国别从 `req.country` 或问句识别后，
  先取该国 law_id 集合，作为 `law_ids=` 前置过滤；
- **RRF**：`k=60`、两路 1:1；BM25 命中的条文保留，纯向量条目须过余弦阈值
  `CALR_QA_VEC_MIN`（默认 0.30）；
- 返回 `mode=hybrid-rrf | bm25-article | no-hit`，每条 citation 带
  `debug.bm25Rank / vecRank / cosine`；生成仍依赖前端 BYOK；
- 向量不可用/模型未加载时自动走 BM25 条文路径，不再返回空；
- 离线测试：`python backend/test_qa_hybrid.py`（5/5 通过，含国别、BM25、RRF 路径）。

**前端 `prototype/assets/js/core/qa.js`**（1,165 行）
- 检索：`CALR.search.run({q, mode:'semantic', size:12, country})` —— 浏览器内 BM25 + 11 组中文同义词扩展（`search.js SYNONYMS`）；**离线模式没有向量**；
- 引用：`buildRefs(top, 5, tokens)`，条内 `minScore = topScore × 0.86` 过滤，最多 6 个要点（`MAX_POINTS`）；
- 拒答：`isNonLegal()` + `outOfJurisdiction()` 法域门禁；`THRESHOLD = 20` 低于则答"暂未收录"（注释标定于 10-17：正例最低 31.5、负例最高 70 —— 按阈值 20 推断应为 `7.0`，**注释笔误**）；
- 预置问答：Jaccard ≥ 0.55 且主题、国别三重门；
- 重排：`rerank.js` 调**用户自带 Key 的 LLM**（MAX_CANDIDATES=20 → MAX_PICK=3），未配 Key 时直接返原序；
- API 模式下会调 `CALR.api.qa()`（`qa.js:1100-1106`）走后端条文向量。

## 2. 瓶颈判定：数据滞后 vs 算法

| 归因 | 证据 | 影响面 | 判定 |
|---|---|---|---|
| **数据滞后（主因）** | 向量 10-24 建，库 10-29 重建；条文覆盖 58.5%、法规 44.6%；MY/ID 1.1% | 41.5% 条文、55.4% 法规**完全无向量**；新入库 23,350 部里 23,259 部进不了语义召回 | **占 70% 权重** |
| 条文向量截断 | `maxLen=160`（manifest）≈ 240 汉字；按嵌入输入（zh+en+orig 拼接）统计，条文长度中位 550、P90 2,858、P99 13,815、max 4,230,590 字符，**76.3% 条文 >240 字符** | 长条文只嵌了开头；双语条文只嵌了前半段（`txt[:2000]` 后仍按 160 token 截） | 15% |

**一句话**：现在不是"向量化方式不够好"，而是"向量化只做了半个库 + 截断太短 + 用法太浅"。

## 4. 是否换/加 embedding 模型

**结论：不换，先"用满"bge-m3。**

理由：

1. **语言覆盖**：本库 12 法域含泰文、越南文、印尼文、缅甸文、高棉文、老挝文、马来文、中文、英文。bge-m3 覆盖 100+ 语言且支持 8192 上下文，是少数"一个模型全包"的选择。
2. **法律领域模型普遍不适用**：InLegalBERT / Legal-BERT / legal-embedding 系列以英文（少量中文）法律语料训练，对泰/越/印尼/缅/高棉基本无效；中文法律专用模型（如 bge-large-zh-v1.5、Conan-embedding-v2）能提升 CN，但 CN 只占 **1,587/42,121 = 3.8%**，为 3.8% 的语料换掉 100% 的模型不划算。
3. **换模型成本被低估**：不只是"再嵌一次"——564k 条文 @ 新模型 ≈ 8–20h + 全量评测重跑 + **所有阈值重标定**（前端 `THRESHOLD=20`、`minScore=0.86`、`CURATED_MIN_SIM=0.55` 都依赖现有分布），至少 1 周，且要重新验证 12 个法域。
4. **现在只用了 bge-m3 的一小部分能力**：只用 dense-CLS 输出、条文截断 160 token、法规只嵌标题、没用到它的 **sparse（lexical weights）** 与 **ColBERT 多向量** 头。把这三件事用起来，收益大于换模型。
5. **如果一定要"加"模型，优先加 bge-m3 的多头输出**（同一模型、同一份权重）：
   - **sparse 头**：可直接替代/补强 BM25 的第二路召回，跨语言比字面 BM25 强；
   - **ColBERT 头**：做轻量重排（交互式打分），比 cross-encoder 便宜得多。
   - 但当前 ONNX 只导出了 dense（`embed-law.log`：输入只有 `input_ids/attention_mask`，`embedder.py` 取 `output[0]` 的 CLS），要用多头必须**重新导出 ONNX 并验证量化精度**（1–2 天）。
6. **离线约束**：2.16 GB 的 ONNX 不可能进浏览器，所以 `file://` 离线模式只能 BM25 + 预置问答（现状即如此）。若"离线也要语义检索"是硬需求，只有两条路：
   - 本机/内网起 `backend`（已支持，`CALR_VEC`/`CALR_MODEL` 可配）；
   - `transformers.js` + 量化小模型（如 bge-small-zh int8 ≈ 30–100 MB）——但只覆盖中文，东盟语种无解，不建议。
7. **不要做的**：不要为了"看起来更先进"换成 API embedding（如 OpenAI/智谱 embedding）——项目红线是本地/内网可跑，且 564k 条向量化的 API 成本与合规风险都不可控。

### 5.3 参数建议

- **RRF**：`k=60` 保留；`bm25_weight/vec_weight = 1.0/1.0` 保留；短查询（≤4 字）向量 ×0.7 保留（实测有效）。
- **条文嵌入**：`maxLen=512` 起步；超长条文按 512 窗口、stride 128 切片，单条最多 3 块，块与块用同一 `(law_id, no, dup_index, chunk)` 键。
- **法规嵌入**：`title(zh/en/orig) + summary + 前 2 条正文`，总长控制在 8192 token 内（bge-m3 支持 8192，不必截到 512）。
- **语言**：一条条文若同时有 zh/en/orig，**分别嵌入成多条向量**（在 metadata 里加 `lang`），而不是拼成一条；检索时按查询语言加权。
- **检索阈值**：两套——BM25 分数量级（几十）用 `THRESHOLD=20`；cosine（0–1）用 `0.45~0.55` 区间，需在扩充后的评测集上标定。
- **国别**：问句点名单国 → 预过滤；点名多国 → 不限制但记录 `countryFilter`；未点名 → 按 `PRIORITY_COUNTRY=CN` 加权（后端已有）。

### 5.4 风险清单

1. **重嵌窗口不一致**：4–20 小时内向量与库不同步。建议写入新目录 + `CALR_VEC` 原子切换，或夜间执行；`vectors.load()` 以 manifest 为就绪标志，写到一半不会误加载，但**切换前 `/api/qa` 仍是旧索引**，需在响应里标注索引时间（建议加 `vectorsBuiltAt`）。
2. **阈值全部需要重标定**：`THRESHOLD=20`、`minScore=0.86`、`CURATED_MIN_SIM=0.55` 都是按旧 BM25 分数分布标的；换向量/加融合后必须重跑 110 题基线。
3. **评测绝对值会下降**：库从 18,785 涨到 42,121，候选池变大，P@3 天然下降；且 gold 是弱标注（1.4% 引用已失效），必须用**同口径相对比较**，否则会误判"改坏了"。
4. **分块会放大向量体积**：条文向量 0.35 GB → 1.0 GB 量级，`backend/data` 已 gitignore，但部署包（`_out/calr-model.tar.gz` 1.26 GB）会变大。
5. **不要用"更先进模型"替代评测**：当前 4 个主题 P@3=0（劳动/税务/土地/金融），先查清是标签问题还是排序问题，再决定是否动模型，否则换了模型也不知道有没有变好。
