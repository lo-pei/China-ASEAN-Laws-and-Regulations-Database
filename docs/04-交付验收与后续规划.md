### 2.2 数据自足性的 11 项检查（A1–A11）

| 项 | 内容 |
| :--- | :--- |
| A1 | `laws/index.json` 与 `laws/*.json` 一一对应 |
| A2 | index.json 的 lawCount / articleCount / chars 与逐文件统计一致 |
| A3 | 每部法的 articleCount 与 articles.length 一致；条文 id / no 唯一 |
| A4 | `packFor` 可解析：法规的 layer+pack 能在分卷中找到 |
| A5 | 译文 manifest 声明的每个分卷存在；byLaw 每条都能在文件中找到 |
| A6 | 译文条目的 lawId 必在 `laws/`；条号必为真实条号 |
| A7 | 标题译名存在时 `title.zh` 必须存在 |
| A8 | **无外部依赖**：所有数据文件都在 `prototype/` 内 |
| A9 | `titles.zh.json` 的 translatedCount 与`laws/`实际有中文标题的条数一致 |
| A10 | `titles.zh.json` 与 `laws/` 的 `title.zh` 逐条一致，且不含已删法规 |
| A11 | 分卷抽样可解析且命中 `packFor` 映射 |

> **A8 是项目形态的守门项**：一旦有数据引用 `prototype/` 之外的路径，
> 「拷走 `prototype/` 即可完整运行」这条承诺就破了。

## 三、检索质量评测

### 3.1 评测集

`_work/rag/gold.json`：**110 道题**（含 4 道负例），按 12 法域、主题均匀分布。
金标是**机械弱标注**（按关键词 IDF 从全库挑出的候选），因此**绝对值低估真实效果**，
只应看**相对变化**。

### 3.2 Phase B 对比结果（106 道有金标的题）

| 方案 | P@3 | R@5 | MRR | 至少命中 | 国别准确 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| BM25（纯词面） | 5.7% | 5.1% | 0.080 | 10.4% | 26.4% |
| 纯向量（bge-m3） | 6.3% | 4.8% | 0.126 | 23.6% | 40.6% |
| RRF 融合 | 15.7% | 13.3% | 0.233 | 40.6% | 96.2% |
| **融合 + 国别约束** | **16.7%** | **13.7%** | **0.262** | 39.6% | **99.1%** |

**相对 BM25**：P@3 **+11.0pt**、R@5 **+8.6pt**、MRR **+0.182**、至少命中 **+29.2pt**、国别 **+72.7pt**

### 3.3 三种方案为什么是互补的

| 查询 | BM25 | 纯向量 | 融合 |
| :--- | :--- | :--- | :--- |
| 民法典 | CN 民法典 #1 | LA 民法典 #1 ✗ | **CN 民法典 #1** |
| 数据法 | VN #1，CN #4 | BN 统计法 #1 ✗ | **VN #1，CN 数据安全法 #2** |
| 个人信息保护 | CN #1–5 | VN 条例 #1 ✗ | **CN #1–5** |

BM25 强在字面精确（文号、全称、条号），向量强在语义等价（同义改写、跨语言），
RRF 只看排名，避开了两者分数不可比的问题。

## 四、已知问题（如实列出）

### 4.1 数据层

| 问题 | 规模 | 影响 | 状态 |
| :--- | :--- | :--- | :--- |
| 条号在文内重复 | 325 部 / 7,917 处 | 译文层与跨层比对需特殊处理 | 已标 `dupIndex`；5 部列「编号不可对齐」例外 |
| 缺中文标题 | 60 部 | 显示原文标题，不空白但阅读成本高 | 需其他语种翻译模型 |
| `heading` 疑似被截断 | 792 部 / 3,335 条 | 列表摘要不准 | 生成器已修，存量需重抓 |
| 缅甸文 OCR 不可读 | 全部缅甸文 PDF | 该语种无法结构化 | 需缅甸文识别模型 |
| 判例未入库 | 1,275 页 | 无判例检索能力 | 3 份缅甸文不可 OCR；2 份英文需判例数据模型 |
| 泰文标题为机翻 | 606 条 | 约六至七成可用 | 标 `reviewed=false`，原文始终可查 |

### 4.2 技术层

| 问题 | 影响 | 计划 |
| :--- | :--- | :--- |
| 条文级向量滞后 | 51 部切分法规仍是旧整段向量 | 重跑条文级向量（GPU 约 4 小时） |
| 前端仍加载分卷与 `bm25-idf.js` | API 模式首屏 2.15 s（可再降到 1 s 内） | 把条文也走 API |
| 无 CI 流水线 | 校验靠手动跑，存在回归风险 | 接入 GitHub Actions |
| 单 worker、无缓存层 | 并发能力有限 | 需先评估 SQLite 只读并发 |

### 4.3 产品层

| 问题 | 说明 |
| :--- | :--- |
| AI 问答只召回不生成 | 后端 `/api/qa` 返回条文依据；生成依赖用户自带 Key（BYOK） |
| 比对报告维度覆盖低 | 单条条文常只涉及 1 个维度，报告偏薄 |
| 无用户系统 | 对话不落盘、无收藏批注（隐私取舍） |
