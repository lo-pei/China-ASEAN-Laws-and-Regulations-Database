## 3. 部署步骤

### 3.1 上传

```bash
# 目标目录示例；按实际部署路径调整
mkdir -p /opt/calr/backend/data/vectors-chunks
rsync -av --progress \
  backend/data/vectors-chunks/ \
  user@server:/opt/calr/backend/data/vectors-chunks/
```

不要上传 `*.before-*`、`*.tmp*`、旧 parts/ckpt；当前已清理。

### 3.2 配置

- 默认目录无需额外配置。
- 自定义目录时设置：

```bash
export CALR_CHUNK_VEC=/opt/calr/backend/data/vectors-chunks
```

- 默认优先 C；回退 A：

```bash
export CALR_QA_CHUNKS=1   # 默认，使用 C
export CALR_QA_CHUNKS=0   # 强制回退 A 条文向量
```

### 3.3 验证

```bash
# 结构与数量（无模型也能跑）
python backend/test_chunk_vectors.py

# 混合问答逻辑
python backend/test_qa_hybrid.py

# 实际 API（服务启动后）
curl -s -X POST http://127.0.0.1:8000/api/qa \
  -H 'Content-Type: application/json' \
  -d '{"question":"越南外商投资准入条件","topk":3}'
```

验收标准：

- `backend/test_chunk_vectors.py` 全部通过；
- `/api/qa` 返回 `mode=hybrid-rrf`，`diagnostics.vecReady=true`；
- 越南问句返回 VN 条文，且 `citations` 带 `lawId/no/noLabel`；
- 设置 `CALR_QA_CHUNKS=0` 后仍可返回结果（A 回退）。

## 4. 重建

```powershell
$env:CALR_MAX_LEN="512"
python _work/phaseb/embed_chunks.py --batch 8
```

- 中断重跑自动从 `chunk_missing.ckpt` 续跑；
- 最终 `chunk_vecs`、`chunk_scale`、`chunk_meta`、`manifest` 写成功后，脚本自动清理 parts/ckpt；
- 全量约 6.5 条/秒，约 26 小时（本机 GTX 1650 Ti / DirectML）；
- 旧产物写前自动复制为 `*.before-chunks`。

## 5. 回滚

- 删除或重命名 `backend/data/vectors-chunks/`；
- 或设置 `CALR_QA_CHUNKS=0` 强制使用 A 索引；
- A/B 索引 `backend/data/vectors/` 不受 C 影响。

## 6. 注意事项

- C 索引只做条文级召回；法规/条文元数据仍来自 SQLite。
- 切片是**单语种**（原文优先，其次中/英），不要把多语拼接回一个向量。
- 检索时按 `(law_id,no,dup_index)` 聚合最高 chunk 分数；不要按 chunk 直接返回引用。
- C 索引体积大，不要提交到 Git；只提交生成代码、测试与本页说明。
