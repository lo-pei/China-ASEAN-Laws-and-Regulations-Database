# 03b · 42k 新库 RAG 评测（2026-10-31）

> 目的：在 C 切片索引完成后，对 **BM25 / A 条文向量 / C 切片向量** 做同口径对比。  
> 结论先行：**C 索引已可用，但在这套 346 题混合集上没有显著优于 A；不能据此宣称“C 提升准确率”。**

## 1. 评测集

`_work/rag/questions-300.json`，共 **346 题**：

| 来源 | 数量 | 说明 |
| :--- | ---: | :--- |
| curated | 106 | 复用 `_work/rag/gold.json` 的既有题，带人工/半人工金标 |
| synthetic | 240 | 12 法域 × 20 题；从 DB 真实条文标题/正文生成，用于覆盖与回归 |
| 合计 | **346** | 12 法域均覆盖 |

合成题模板：

```text
在{国家}，《{法规标题}》中关于“{条文标题/正文前60字}”的规定是什么？
```

**重要限制**：合成题包含法规标题与条文标题，BM25 会天然占优；合成题不能当作人工标注准确率，也不能与旧库 106 题绝对值直接横比。本报告将 curated 与 synthetic 分开列出。

评测口径：

- 法域：问句不显式传 `country`，由 `qa.retrieve` 自行识别/前置过滤；
- 返回：`topk=5`；
- 指标：P@3、R@5、MRR、Hit@5；另算 Article 级 P@3 / R@5 / MRR / Hit@5（引用条号是否命中金标条）；
- 运行环境：本机 GTX 1650 Ti / DirectML，首次含模型加载；延迟为单题 P50/P90。

## 2. 结果

### 2.1 全部 346 题

| 配置 | P@3 | R@5 | MRR | Hit@5 | ArticleHit@5 | P50 | P90 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25 | **34.87%** | 41.72% | 40.04% | 43.93% | 38.44% | 1397ms | 2153ms |
| A 条文向量 + RRF | 32.66% | 58.25% | 52.04% | **65.03%** | **53.76%** | 1565ms | 2539ms |
| C 切片向量 + RRF | 32.47% | **58.63%** | 51.52% | 64.74% | 53.18% | 1591ms | 2368ms |

### 2.2 分开看

| 配置 | curated P@3 | curated ArticleHit@5 | synthetic P@3 | synthetic ArticleHit@5 |
| :--- | ---: | ---: | ---: | ---: |
| BM25 | 10.69% | 9.43% | 45.56% | 51.25% |
| A 条文向量 | **20.44%** | **25.47%** | 38.06% | 66.25% |
| C 切片向量 | 19.81% | 23.58% | **38.06%** | **66.67%** |

### 2.3 解读

1. **BM25 在全部题上 P@3 最高**，主要因为 synthetic 题大量包含法规标题，词法匹配占优；但其 R@5 / ArticleHit 明显低于向量路。
2. **A 与 C 的向量路整体接近**：C 的 R@5 略高（+0.38pt），ArticleHit 略低（-0.58pt），P@3 低 0.19pt；差异不足以证明 C 更优。
3. **curated 子集**上 A 略优于 C（P@3 20.44% vs 19.81%，ArticleHit 25.47% vs 23.58%）；C 没有在人工题上体现出“长条文切片”优势。
4. 国别准确率整体约 43%，curated 仅约 20%；**国别识别/过滤仍是主要短板**，与向量层无关。
5. C 的候选聚合已改为“多取 chunk、按条聚合”，复测结果与首轮基本一致，说明问题不在候选数量，而在当前评测集与短条文场景下 C 的收益有限。

## 3. 结论与建议

### 3.1 不要宣称 C 提升准确率

对外材料应表述为：

> “C 阶段完成 512-token 单语种条文切片索引；混合问答支持 C/A 双索引与自动回退。在新库 346 题混合评测中，C 与 A 整体接近，尚未观察到稳定增益。”

不要写“C 显著提升 P@3”或使用未经验证的数字。

### 3.2 默认索引策略

当前代码默认 `CALR_QA_CHUNKS=1`（优先 C）。评测后建议：

- 若目标是**保守准确率**：先设 `CALR_QA_CHUNKS=0` 使用 A，C 作为可选能力保留；
- 若目标是验证长条文/多语长文档：保留 C，并补做题级长条文评测后再决定默认值；
- 不建议在未完成人工评测前，把 C 写成“效果更好”的卖点。

### 3.3 下一步

1. 用**人工/半人工 curated 300+** 替换 synthetic 主体，按法域与主题分层；
2. 单独构造 50–100 道长条文（>512 token）题，验证 C 的切片收益；
3. 对国别识别做专项评测与修复（当前 curated CountryAcc 约 20%）；
4. 再调 `CALR_QA_VEC_MIN` / `CALR_QA_RRF_K` / 候选数量；
5. 最终决定默认用 A 还是 C，并把结论回填 README/PPT/申报书。
