# 产品解决方案包（solution/）

面向 **2026 中国（广西）—东盟“AI+法律”应用创新大赛** 评审与答辩的产品解决方案材料：
一页式交互 Demo + 正式说明书。**不替代产品本身**，真实产品在 [`../prototype/`](../prototype/)。

---

## 一、打开方式

| 文件 | 用途 | 怎么打开 |
| :--- | :--- | :--- |
| [`index.html`](index.html) | 交互 Demo（零依赖、可离线） | 双击用浏览器打开；答辩时全屏投影 |
| [`产品解决方案说明书.docx`](产品解决方案说明书.docx) | 正式说明书（Word） | Word / WPS |
| [`产品解决方案说明书.pdf`](产品解决方案说明书.pdf) | 正式说明书（PDF） | 任意 PDF 阅读器；适合提交 |
| [`产品解决方案说明书.md`](产品解决方案说明书.md) | 说明书源文档 | 便于后续修改与版本管理 |

> Demo 内所有「打开真实产品」按钮都指向 `../prototype/index.html`；整个 `solution/` 与 `prototype/` 需放在同一项目目录下。

## 二、答辩讲解动线（3 分钟版）

1. **0:00–0:30 问题**：东盟投资与涉外业务要查 12 个法域的法律，文本分散、语言不通、AI 答案不可核验。
2. **0:30–1:10 方案**：打开 Demo §方案总览 —— 一句话：「把可溯源做成工程约束，把跨语言做成检索能力」；三层架构：权威数据底座 → 混合检索 → 可引用问答。
3. **1:10–2:10 产品**：切到 §产品演示，依次点 6 个 Tab：
   - 检索：12 法域、多维筛选；
   - 详情：原文 + AI 译文逐条对照、条文目录；
   - 比对：中越条款并列、五维对照；
   - 问答：每条回答带条文出处；
   - 术语/引注：术语对照与规范引注。
4. **2:10–2:40 数据与工程**：18,785 部 / 339,351 条；权威存储单一化；6 条红线；7 个校验器 CI 全绿。
5. **2:40–3:00 价值**：点「打开真实产品」现场演示 `file://` 零依赖运行；说明落地形态与路线图。

> 5 分钟版：在两处展开——混合检索（BM25 + 向量 + RRF 的互补性）与数据治理（红线 + 校验 + 自足性）。

## 三、Demo 内容结构

`index.html` 为单页应用，共 10 个章节：

1. Hero（12 法域 / 18,785 部 / 339,351 条 / 1,566 部译文）
2. 为什么需要它（4 个痛点）
3. 方案总览（三层架构 + 三个设计原则）
4. 产品演示（6 个 Tab：检索 / 详情 / 比对 / 问答 / 术语 / 引注）
5. 数据底座与治理（12 国真实分布、红线、校验）
6. 技术架构与实测指标
7. 差异化（通用大模型 / 商业库 / 官方门户）
8. 应用场景
9. 落地形态与路线图
10. 团队、交付物与免责声明

技术：纯 HTML/CSS/JS，无构建、无 CDN、无外部字体；数据来自 `assets/data/sample-laws.js`，
图片来自 `assets/shots/`（`prototype/` 真实界面截图，2026-10-24）。

## 四、数据与口径

- 所有统计数字以 [`../docs/README.md`](../docs/README.md) §三 为准；
- Demo 中的法规标题、条文原文、译文片段均从 `prototype/data/` 真实数据抽取，**未改写、未编造**；

- 说明书中的评测数字来自 110 题弱标注评测集，绝对值偏低估，只应看相对提升。

## 五、再生成

- **Demo**：直接编辑 `index.html` / `assets/css/solution.css` / `assets/js/solution.js`；刷新浏览器即可，无构建步骤。
- **说明书**：编辑 `产品解决方案说明书.md` 后运行
  `python solution/tools/build_docx.py solution/产品解决方案说明书.md solution/产品解决方案说明书.docx`，
  再用 LibreOffice / Word 导出 PDF（或 `soffice --convert-to pdf`）。
- **截图**：如需更新，使用 Edge headless 截 `prototype/` 页面后替换 `assets/shots/` 下同名文件。
  > Windows 上 `msedge --headless --window-size=390` 会把布局视口钳制在约 496px，截图会被裁成 390px，
  > 看起来像横向溢出；移动端检查请用 DevTools 设备仿真或真机，不要用该 CLI 截图判断。
