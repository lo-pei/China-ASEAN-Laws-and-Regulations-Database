## 2. Demo 规格（demo-builder）

### 2.1 定位
一页式“产品解决方案”演示，面向答辩现场：既能自己滚动讲，也能随时跳到真实产品。**零外部依赖**：不能有 CDN、外部字体、远程图片；`file://` 双击可开；数据从 `assets/data/sample-laws.js` 读取（普通 `<script>`，不要 `fetch`）。

### 2.2 文件
- `solution/index.html`
- `solution/assets/css/solution.css`（或拆 tokens/layout）
- `solution/assets/js/solution.js`
- 图片只用 `solution/assets/shots/` 下三张真实截图：
  - `law-detail.png`（1440×940，民法典详情，原文+AI 译文+条文目录）
  - `search-results.png`（897×880，检索结果卡片列）
  - `home-hero.png`（1440×360，首页标题+检索框，已裁掉过期统计）

### 2.3 章节（顺序固定）
1. **Hero**：主标题「东盟法律，一库通查」；副标题「面向 12 法域的法律检索、跨语言比对与可溯源 AI 问答平台」；4 个数字（12 法域 / 18,785 法规 / 339,351 条文 / 1,566 部译文）；两个 CTA：「打开真实产品」→ `../prototype/index.html`，「3 分钟看完方案」→ 锚点。
2. **为什么需要它**：4 张痛点卡（法域分散/语言壁垒/溯源困难/通用 AI 不可信）。
3. **方案总览**：一句话方案 + 三层架构图（数据底座 → 检索引擎 → 应用与问答）+ 三个设计原则（可溯源、跨语言、AI 可解释）。
4. **产品演示**（核心，Tab 切换，6 个 tab）：
   - 法规检索：截图 `search-results.png` + 要点（名称/文号/关键词/条号；12 法域、主题、层级、时效筛选）
   - 法规详情：截图 `law-detail.png` + 要点（原文与 AI 译文逐条对照、条文目录、文内查找、导出）
   - 跨语言比对：用 `compare.left/right` 的真实原文并列展示（中文/越南文），标注来源；展示五个维度标签（适用范围/核心概念/法律后果/程序与期限/门槛与标准），**只展示待比对维度，不编造结论**
   - AI 智能问答：用 `qa[0]` 做一行真实问答：问题 → 引用原文（逐字）→ 出处 chip（法规名 + 条号）→「AI 辅助生成，仅供参考」；可再加 `qa[1]` 折叠
   - 术语对照：用 `terms`（5 组真实 zh/en）做小卡片/表格
   - 规范引注：只用说明性文案 + 格式标签（GB/T 7714-2015 / Bluebook / 简化式 / 完整式），不要伪造完整引注字符串
5. **数据底座与治理**：真实 `countryCounts` 横向条形图（12 国）；权威存储 `laws/*.json` → 派生分卷/DB/向量；6 条红线；校验体系。
6. **技术架构**：前端零构建 SPA / FastAPI + SQLite / BM25 + bge-m3 向量 + RRF / ONNX；指标卡（P@3、国别准确、P50、首屏、DB 大小、CI 全绿）。
7. **差异化**：与「通用大模型」「商业法律数据库」「官方门户」的定性对比表；强调可溯源、离线可跑、数据自足、成本低。
8. **应用场景**：法官/仲裁、律师/企业法务、高校教研、涉外政务服务 4 个场景卡。
9. **落地与路线**：三种部署形态 + 短/中/长期路线（见 docs/04 §五）。
10. **团队与交付**：团队名、可复现命令、文档/产品链接、免责声明 footer。

### 2.4 交互与质量
- 顶部固定导航 + 阅读进度条；smooth scroll；当前章节高亮。
- Hero 数字滚动动画（IntersectionObserver，尊重 `prefers-reduced-motion`）。
- Tab 键盘可用（←/→，role=tab）；搜索演示支持输入与快捷词（`sampleQueries`），按 `title/titleEn/countryName` 过滤，空态友好；结果可点开侧栏/弹层，显示元数据 + 「在真实产品中打开」链接 `../prototype/index.html#/law/<id>`。
- 响应式：1440 / 768 / 390 三档；移动端导航折叠。
- 不使用 alert/console error；语义化标签；图片有 alt；颜色对比度合格。
- 设计方向：深海军蓝 + 米白 + 少量金色；标题宋体感、正文无衬线；大数字、细网格、克制的动效；不要 Bootstrap 模板感。
- 主题 token 建议：`#0A1B33 / #12305A / #C6A15B / #F7F4EC / #1E2430 / #5C6675`。
- 所有数字从 `CALR_SOLUTION_DATA.meta` / `countryCounts` 读取，不硬编码（个别文案除外）。
- 链接检查：`../prototype/index.html`、`../docs/README.md`、`../README.md`、`../CHANGELOG.md` 均可达。

### 2.5 自检
用 Edge headless 截图三档宽度并存到 `_work/_solution/qa/`（不提交），检查无溢出/重叠/空白；报告一次 `node --check assets/js/solution.js` 结果。截图命令示例：
`msedge --headless --disable-gpu --hide-scrollbars --window-size=1440,1000 --virtual-time-budget=3000 --screenshot=<out.png> "file:///<abs>/solution/index.html"`

## 3. 说明书规格（doc-writer）

### 3.1 文体与篇幅
- 中文正式说明书，面向评审；**8,000–9,500 汉字**（不含表格代码），约 14–18 页。
- 具体、可验证、有取舍；不堆形容词；已知限制单列一节。
- 只写 Markdown（GFM 表格），不要 HTML。允许相对链接（如 `../docs/04-交付验收与后续规划.md`）。

### 3.2 结构（H2 固定，可加 H3）
| 章节 | 内容要求 | 建议字数 |
| :--- | :--- | ---: |
| 摘要 | 问题、方案、数据、验证、价值，一段 300–400 字 | 350 |
| 一、背景与问题 | 涉外法治/东盟经贸带来的法律查明需求；现有方案三道缺口（分散、语言、不可信），定性为主 | 700 |
| 二、产品定位与目标用户 | 一句话定位；4 类用户与各自任务；与“通用 AI/搜索引擎”的边界 | 700 |

| 四、核心功能 | 7 项功能逐一：做什么、怎么用、为什么可信；配 2 张真实截图占位 | 1,300 |
| 五、数据资产与治理 | 规模表、权威存储单一化、译文层/标题层、6 条红线、9 条质量约束、校验体系 | 1,200 |

### 3.4 必须包含的表格
数据规模表、指标实测表、差异化对比表、路线图表、交付物/校验表、附录数据口径表。
所有数字以 §1 事实表为准；引用评测数字时注明“110 题弱标注评测集，绝对值偏低估，看相对提升”。

### 3.5 禁止
- 不写“全球领先/第一/唯一”等绝对化结论；不写未经验证的客户、收入、市占率。
- 不把“译文”写成人工校验；不把“AI 问答”写成自动生成法律意见。
- 不承诺判例检索、用户系统等尚未实现的功能。

## 4. 完成标准
- Demo：三档截图无布局问题；交互可用；无外链依赖；所有数字与事实表一致；真实法条只来自样本数据。
- 说明书：字数达标；章节齐全；数字一致；无编造；Markdown 表格规范；图片占位准确。
- 完成后将产出文件写到指定路径并回报：字数/章节数、Demo 自检截图路径、遇到的取舍。
