# 全文数据集规范（v1.0）

> 本规范是「法条数据库主体」建设的执行契约。目标：把 `prototype/data/` 中的演示性节选条文，替换为**来自各国官方法律数据库的法规全文**，并保证可核验、可追溯、不节选、不编造。
> 本文件与 `docs/00-项目基线.md` 第 6 节配套使用；两者不一致时以本规范为准（仅限全文数据部分）。

---

## 1. 基本原则（四条红线）

1. **逐字不节选**：条文正文必须与官方来源**逐字一致**。禁止改写、概括、合并、精简、补全；禁止使用「……」、`（略）`、`（下略）`、`等`、`摘录`等省略标记；禁止只录入前若干条。
2. **不编造**：任何条号、标题、正文、施行日期都必须来自实际抓取的官方页面。**抓不到就标记为未获取，绝不臆造**。官方原文缺失的内容（例如某条官方无标题）宁可为空，不可自拟。
3. **来源可追溯**：每条法规必须给出 `sourceName`、`sourceUrl`、`fetchedAt`（抓取日期）；有条件时逐条给出条文级 `sourceUrl`。
4. **语言标注准确**：`language` 必须是该官方文本的**实际语言**（`zh`/`en`/`vi`/`th`/`id`/`ms`/`my`/`km`/`lo`/`pt`）。**译文不得冒充原文**；若来源提供官方法定英文版，可另存为 `textOfficialEn` 之类字段并注明版本。

## 2. 文件布局

```
prototype/data/
├── dataset-core.js          # 元数据 + 基础条文（演示数据，保留为兜底）
├── dataset-extra.js         # 术语 / 条约 / 案例 / 修订 / 问答
└── fulltext/                # 【新增】官方全文，按法域分文件
    ├── manifest.js          # 索引：哪些法域有全文文件、每个法规归属哪个法域
    ├── cn.js
    ├── ph.js
    ├── sg.js
    ├── my.js
    ├── id.js
    ├── th.js
    ├── vn.js
    ├── bn.js
    ├── kh.js
    ├── la.js
    ├── mm.js
    └── tl.js
```

* 每个法域文件是一个**零依赖传统脚本**（不得使用 `import`/`export`/`fetch`），形如：

```js
(function (root) {
  'use strict';
  root.CALR_FULLTEXT = root.CALR_FULLTEXT || {};
  root.CALR_FULLTEXT['CN-FIL-2019'] = { /* 见第 3 节 */ };
})(typeof window !== 'undefined' ? window : globalThis);
```

* **键必须是 `dataset-core.js` 中已存在的法规 id**（形如 `CN-FIL-2019`）。若要**新增法规**，在该法域全文文件中同时登记元数据（见下），**不要修改 `dataset-core.js`**（避免多个文件互相覆盖）：

```js
(function (root) {
  'use strict';
  root.CALR_FULLTEXT = root.CALR_FULLTEXT || {};
  root.CALR_FULLTEXT_META = root.CALR_FULLTEXT_META || {};   // 仅新法规需要

  /* 新法规：只登记元数据（字段与 dataset-core.laws[] 一致，但不含 articles） */
  root.CALR_FULLTEXT_META['CN-DATA-EXPORT-2022'] = {
    country: 'CN', level: 'subdecree', status: 'active', topics: ['data'],
    title: { zh: '数据出境安全评估办法', en: 'Measures for the Security Assessment of Data Export' },
    docNumber: '国家互联网信息办公室令第11号',
    issuingBody: { zh: '国家互联网信息办公室' },
    promulgatedDate: '2022-07-07', effectiveDate: '2022-09-01',
    coverage: 'full', source: { name: '国家法律法规数据库', url: 'https://flk.npc.gov.cn/' },
    summary: { zh: '……', en: '……' }
  };

  root.CALR_FULLTEXT['CN-DATA-EXPORT-2022'] = { /* 第 3 节契约 */ };
})(typeof window !== 'undefined' ? window : globalThis);
```

* 元数据字段要求：`country / level / status / topics / title / issuingBody / promulgatedDate / effectiveDate` 必填，`docNumber / summary` 尽量填写；**不确定的字段留空或省略，不得编造**。
* 新增法规的 id 规则：`{国家代码}-{主题缩写}-{年份}`，同一法域内不得重复。

## 3. 数据契约

```js
root.CALR_FULLTEXT['CN-FIL-2019'] = {
  id: 'CN-FIL-2019',
  coverage: 'full',                       // 固定 'full'；节选一律不得写入本目录
  language: 'zh',                         // 官方文本语言
  sourceName: '中国政府网（国务院公报）',     // 官方来源名称
  sourceUrl: 'https://www.gov.cn/...',    // 实际抓取的正文页 URL
  fetchedAt: '2026-10-02',                // 抓取日期（本地日期）
  articleCount: 6,                        // 条文总数（必须 = articles.length）
  completenessNote: '全文，含第一条至最后一条；官方文本未分章',
  structure: [                            // 章节结构（可选，用于目录与折叠）
    { zh: '第一章 总则', articles: [1, 2, 3] },
    { zh: '第二章 投资促进', articles: [4, 5] }
  ],
  articles: [
    {
      id: 'CN-FIL-2019-A1',               // 规则：<lawId>-A<条号数字>
      no: 1,                              // 条号数字，用于精确检索与排序
      noLabel: { zh: '第一条' },           // 官方条号写法
      chapter: { zh: '第一章 总则' },       // 所属章/节（官方无章节时留空对象）
      heading: { zh: '立法目的' },          // 官方条文标题；官方无标题则省略该字段
      text: { zh: '……逐字正文……' },        // 官方原文，逐字
      paragraphs: ['第一款原文', '第二款原文'], // 可选：分款原文（与 text 合并后应等于完整条文）
      sourceUrl: 'https://...'             // 可选：条文级来源
    }
  ]
};
```

字段规则：

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `id` / `no` / `noLabel` / `text` | ✅ | `text` 为该条**全部**文字；多款可用 `\n` 连接或使用 `paragraphs` |
| `chapter` | ✅（可为空对象） | 官方无章节时写 `{}` |
| `heading` | ⭕ | 官方无标题不得自拟 |
| `sourceUrl` | ⭕ | 条文级链接（如该国按条渲染） |
| `structure` | ⭕ | 用于目录；条目里的 `articles` 是**条号数组** |

## 4. 录入规则

1. **条号**：使用官方写法。罗马数字、`Article 1`、`Điều 1`、`第 1 条`、`มาตรา 1`、`Pasal 1` 等按原文保留在 `noLabel`；`no` 用阿拉伯数字。
2. **款/项/目**：保留官方层级。可用 `paragraphs` 数组逐款存放，或在 `text` 内用换行分段。**不得把多款合并成一段**。
3. **修正与非正文内容**：删除网页导航、页脚、广告、版权声明、检索框等非法律文本；删除"（本页最后更新…）"之类非条文内容；但**法律正文中的括号说明、但书、附件目录必须保留**。
4. **官方勘误**：若官方文本含明显排版错误，按官方原文照录，不得自行更正。
5. **附件与附表**：属于法律组成部分的附件，作为一条独立条目（`noLabel: '附件'`，`no` 取该法条文数 + 其后序号）或在 `completenessNote` 中明确说明附件未收录的原因。
6. **章节目录**：`structure` 仅用于导航，不影响条文正文。
7. **体量**：单条条文避免超长；超长条文（如民法典部分条文）照实录入，不得截断。

---

## 5. 完整性自检（交付前必须逐条执行并把结果写入回报）

| 编号 | 检查项 | 通过标准 |
| :--- | :--- | :--- |
| C1 | 条号连续 | `articles.map(a => a.no)` 从首条到末条连续（官方跳号者须在 `completenessNote` 说明） |
| C2 | 条数一致 | `articleCount === articles.length` |
| C3 | 首末条对齐 | 首条 = 官方第一条；末条 = 官方最后一条（对照官方目录页或以官方正文末尾的落款/附则判定） |
| C4 | 无省略标记 | 全文不含 `……`、`（略）`、`（下略）`、`摘录`、`节选`、`待补` |
| C5 | 无网页噪声 | 不含导航词（如"首页｜法律法规｜检索"）、广告、点赞、分享、版权行 |
| C6 | 语法合法 | `node --check <文件>` 通过；Node 中加载后结构与本节契约一致 |
| C7 | 来源可回访 | 用 `web_fetch` 重新抓取 `sourceUrl` 能看到同样的首条与末条文字 |

---

## 6. 抓取不到时的处理

* 只能拿到**摘要或目录**、需要登录、需 JS 交互且无接口、或只有图片型 PDF：**不要写入 fulltext 目录**。
* 在回报中登记为「未获取全文」，写明：法规 id、官方来源、尝试的 URL、失败原因、建议的替代来源。
* 该法规继续使用 `dataset-core.js` 中的节选条文，原型界面会显示「收录形态：节选（待补全文）」。

---

## 7. 交付与回报格式

每个抓取任务交付：
1. 若干 `prototype/data/fulltext/<cc>.js` 文件；
2. 更新后的 `prototype/data/fulltext/manifest.js`；
3. 一份回报（≤400 字）：
   - 表 1：已获取全文的法域 / 法规 id / 条数 / 来源名称 / 来源 URL / 语言；
   - 表 2：**未获取全文**清单（法规 id / 尝试来源 / 失败原因）；
   - C1–C7 自检结论（逐项 通过 / 不通过 + 说明）。

> 说明：本目录只收录**官方法律文本**。绝大多数国家的法律、法规、国家机关决议决定等官方文件不受著作权保护，可依法收录；但官方公报的版式、数据库汇编与第三方译文可能受保护，因此只录入法条正文，不复制版式与第三方译文。
